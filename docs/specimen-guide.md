# C# 표본 제작 가이드

C# 갤러리 전용 규칙이다. 모든 갤러리가 지키는 공통 규칙(meta 글쓰기, 콘텐츠 정책, 무대 계약, 검사)은 kit 의 `docs/kit-guide.md` (`node_modules/@koohoo/gallery-kit/docs/kit-guide.md`) 를 따른다.

## 0. 이 갤러리는 무엇인가 (2026-11-24 Jay 결정)

- **교안을 띄워 두고 옆에서 쓰는 보조 교안**이다. 강사는 교안 원본으로 가르치고, 메모리와 출력이 어떻게 바뀌는지는 이 갤러리로 한 줄씩 보여 준다.
- **교안의 목차와 주제를 그대로 따른다.** 표본은 교안 장의 절 순서대로 만들고, 교안의 코드 예시를 거의 그대로 실행한다. 그 흐름은 비전공자 수업용으로 짠 것이라 (조건문·반복문이 나오는 때까지 맞춰 놓았다) 갤러리가 순서나 주제를 바꾸지 않는다.
- **아직 배우지 않은 문법을 쓰지 않는다.** 교안 코드 블록에 이미 있는 것은 그대로 두지만, 표본을 위해 덧붙이는 코드는 그 장과 앞 장에 나온 문법만 쓴다 (예: 01~04장 표본에 for · while · 메서드 · 클래스를 새로 넣지 않는다).
- Unity 는 신경 쓰지 않는다. `unity` 글은 공통 기본값 `CONSOLE_UNITY` 를 쓴다.
- 지금 범위는 교안 Part 1 의 01 변수, 02 자료형, 03 연산자, 04 콘솔 입출력이다. 그 전에 만든 표본 15개는 내렸다 (커밋 `c0294e0` 에 남아 있다).

## 1. 기준 샘플과 파일

| 표본 | 무엇의 기준인가 |
|---|---|
| `variable-four-stages` | 교안 코드를 줄 번호까지 그대로 옮긴 원본, 교안의 강조 줄 = 단계, 선언만 한 변수(값 없음 상자), 교안 4.3 ❌/✅ 를 `#if GALLERY_MISTAKE` / `#else` 로, 컴파일 오류형 효과 끄기, `CONSOLE_UNITY`, meta 글 |

```text
samples/<id>/<Name>.cs          원본. 교안처럼 최상위 문(클래스·Main 없이)으로 쓴 콘솔 프로그램 (C# 9). .cs 하나
src/specimens/<id>/meta.ts      글, 입력값(params), 단계 (타입은 src/stage/types.ts 의 CsMeta)
truth/<id>/trace.json           npm run trace -- <id> 가 만든 실행 기록 (생성물, 커밋)
```

- `id` 는 kebab-case 영어로, 장의 주제가 드러나게 짓는다 (`variable-four-stages`, `console-tryparse`). 영구 불변.
- 그룹은 `A` (교안 Part 1). `order` 는 **장 번호 × 10 + 장 안 순서** (01장 첫 표본 11, 03장 넷째 표본 34). 갤러리 목록이 교안 목차 순서가 된다.
- `concept` (카드 칩) 은 교안의 장과 절: `'01. 변수 · 3.2 · 4.2 · 4.3'`. 강사가 교안의 어디에 맞는 표본인지 바로 찾게 한다.
- `title` 은 교안 절 제목을 살린다. `lecture` 의 첫 번째가 그 장의 교안 주소다.

## 2. 원본 코드 (`samples/<id>/<Name>.cs`)

- **교안 코드 블록을 그대로 옮긴다.** 줄, 주석, 변수 이름, 값을 바꾸지 않는다. 표본 하나가 교안 코드 블록 하나면 줄 번호도 교안과 같게 한다 (첫 줄부터 교안 코드). 여러 블록을 이으면 블록 사이에 빈 줄과 `// ── 3.4 논리 연산자 ──` 같은 절 표시 주석을 둔다.
- 교안 블록이 그 자체로 컴파일되지 않으면 (앞 블록의 변수를 쓰는 조각 등) 필요한 선언만 최소로 덧붙이고, 덧붙인 줄에 `// (교안 앞 절에서 이어짐)` 처럼 밝힌다.
- 첫 줄은 주석이어야 한다 (교안 블록이 주석으로 시작하면 그것으로 된다. 아니면 무엇을 보여 주는지 한국어 주석 한 줄).
- `using System;` 은 쓰지 않아도 된다 (교안처럼). 기록 도구가 1번 줄 앞에 붙여 컴파일한다 (줄 번호 그대로).
- **짧게.** 무대 코드 칸은 37줄이 보인다. 기본 실행 10칸 이상(썸네일이 7칸째), 200칸 안팎 이하.
- 시드 없는 `new Random()` 은 쓰지 않는다.

### 기록 도구가 보여 주는 것 (코드를 이렇게 쓴다)

기록 도구는 문장 앞마다 `__T.L(줄, 보이는 변수...)` 를 끼워 실행한다.

- **선언만 한 지역 변수** (`int playerGold;`) 는 점선 상자 '값 없음 (int)' 으로 보인다. 값이 확실히 정해진 뒤에 값이 보인다 (Roslyn 확정 할당 분석).
- **`Console.ReadLine()`** 은 입력값 `stdin` 으로 미리 정한 입력을 읽는다 (4절). 읽은 줄은 콘솔 칸에 사람이 친 것처럼 찍힌다 (`당신의 이름은? 홍길동`).
- bool 은 메모리에 C# 표기(`true`)로, 콘솔에는 .NET 출력(`True`)으로 보인다. 글에서 둘을 섞지 않는다.
- 문자열은 힙 객체가 아니라 값처럼 상자 안에 그린다. 배열은 힙 객체와 참조 화살표로 그린다.
- `else if (조건)`, `for` · `while` 의 조건 검사는 칸이 되지 않는다 (지나친 `else if` 줄에 지나간 줄 표시가 없다).
- 메서드·람다·ref·박싱도 그리지만 (plan.md 4절) 01~04장 범위에서는 쓰지 않는다.
- 기록은 1500칸, 20초에서 끊는다.

## 3. 단계와 효과 끄기

- 단계 n 은 원본의 코드 줄 끝 `// [n]` 표시다. 무대의 단계 보기는 **그 줄을 처음 실행한 직후**에 멈춘다 (그 줄이 →, 그 줄이 바꾼 값이 노랗게). `body` 는 "~한 직후다", "~했다" 로 쓴다.
- 단계는 교안이 강조하는 줄(코드 블록의 `hl_lines`, 본문이 짚는 줄)에 둔다. 단계 `label` 은 교안의 말을 쓴다 (`1. 선언`).
- 주석만 있는 줄에 `// [n]` 를 두지 않는다. 표시 줄은 기본 입력의 실행이 실제로 지나가야 한다 (검사).
- `#if GALLERY_MISTAKE` 구역 안의 줄에는 `// [n]` 를 두지 않는다 (효과 끄기 실행이 지나지 않는다).
- `// @param` 과 단계를 한 줄에 두려면 `// @param key // [n]` 처럼 단계 표시를 줄 끝에 둔다. 무대는 두 표시를 지우고 보여 주므로 화면의 코드는 교안과 같다.
- **효과 끄기 = 교안의 ❌ 상황.** `#if GALLERY_MISTAKE` 쪽에 교안의 ❌ 코드를, `#else` 쪽에 ✅ 코드를 둔다. 교안의 4.3 ❌/✅, 4절 Before/After, 8절 주의사항의 실수에서 고른다.
  - ❌ 가 **컴파일 오류**여도 된다 (CS0165, CS0029, CS0664 등). 기록 도구가 오류 줄과 메시지를 기록하고, 무대는 그 줄을 빨갛게, 콘솔에 `컴파일 오류: 22번 줄 · CS0165: …` 를 보인다. 메모리 칸에는 "한 줄도 실행되지 않는다" 가 보인다. offNote 에 이 화면을 쓴다 (오류는 읽는 줄 등 컴파일러가 짚는 줄에 난다. 기록에서 확인한다).
  - ❌ 가 실행되는 실수면 (정수 나눗셈, Trim 누락, FormatException 등) 효과 끄기 실행의 출력·메모리가 갈리는 것을 보인다.

## 4. 입력값 (`params`)

- `select` 와 `toggle` 만 쓴다. 기록 도구가 모든 조합을 미리 실행해 둔다 (최대 12조합, 각 조합마다 보통 실행과 GALLERY_MISTAKE 실행).
- 코드의 값: 원본의 선언 줄 끝에 `// @param <key>` 를 붙인다 (`int playerLevel = 1; // @param playerLevel`). 기록 도구가 그 초기값을 바꿔 실행하고, 무대도 같은 자리를 바꿔 보여 준다. `value` 는 C# 식 그대로 (`'30'`, `'"홍길동"'`). 첫 값(기본)은 교안 값이다.
- **콘솔 입력: key 가 `stdin` 인 select.** 값은 `Console.ReadLine` 이 차례로 읽을 줄들을 `|` 로 이은 것이다 (`'홍길동|2000'`). 원본에는 표시를 달지 않는다. 기본 값은 교안 본문이 예로 드는 입력.
- 입력값이 콘솔이나 메모리에 눈에 띄는 차이를 만들어야 한다. `presets` 2~5개.

## 5. meta.ts

- `import type { CsMeta }` 와 `../../stage/types.ts` 의 `EXEC_EVENTS`, `CONSOLE_UNITY` (그리고 필요하면 `STDIN`) 만 import 한다 (Node 가 직접 읽는다. 확장자 `.ts` 필수).
- `events: EXEC_EVENTS`, `unity: CONSOLE_UNITY` 그대로. 자동 데모(`demo`)는 두지 않는다.
- 글은 교안의 말과 용어를 쓴다 (선언 · 할당 · 초기화 · 재할당, 값 형식 · 참조 형식, 파싱, 정규화). 교안에 없는 비유는 넣지 않는다 (비유는 강사가 말로 한다).
- `goals` 3~4, `mistakes` 3~5 (교안 8절 주의사항에서), `steps` 2~5, `presets` 2~5 (kit 규칙).
- `related` 는 그 장 교안 주소 `{ url, title, why }`, 같은 장의 다른 표본 `{ id, why }`.

## 6. 작업 순서와 검사

```bash
npm run trace -- <id>                 # 기록 (.NET SDK 10). 여러 표본을 동시에 기록할 때는 --no-build
node tools/gallery.mjs check <id>     # 표본만 넣은 빌드: meta 규칙, 무대 동작, 도메인 검사 (원본, 기록 지문, 조합)
node tools/gallery.mjs live <id> --query="auto=0&step=2" wait:800 stage:step2
node tools/gallery.mjs live <id> --query="auto=0&off=1&t=4" wait:800 stage:off
node tools/gallery.mjs thumbs <id>
```

- 원본을 고치면 기록을 다시 만든다. 지문이 다르면 검사가 실패한다 (기록 도구를 고쳐도 마찬가지).
- 완료 체크리스트는 kit-guide 7절. 여기에 더해: 콘솔 출력이 교안의 출력 주석·meta 글의 숫자와 같은지, 효과 끄기 화면이 `offNote` 와 같은지 눈으로 본다. 교안의 출력 주석이 실제 출력과 다르면 표본을 고치지 말고 보고한다 (교안 수정 거리).
