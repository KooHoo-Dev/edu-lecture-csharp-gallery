# C# for Unity

사용자가 C# 기초 개념을 묻거나 그 개념과 관련된 버그를 겪으면 아래 목록에서 가장 가까운 표본을 고르고, 그 표본의 `references/<id>/guide.md` 만 읽는다. 다른 표본의 자료는 읽지 않는다.

## 목록

| ID | 이름 | 분류 | 설명 |
|---|---|---|---|
| `variable-reassign` | 재할당은 갈아 끼우기 | 변수와 재할당 | `gold = gold + reward` 는 gold 의 지금 값을 읽어 계산한 새 값으로 상자 하나의 속을 갈아 끼운다 |
| `float-precision` | 실수는 근삿값 | 실수 자료형 | 0.1 을 열 번 더해도 float 는 1 에서 조금 어긋나고 decimal 은 정확히 1.0 이 된다. 그래서 실수는 `==` 로 비교하지 않는다 |
| `integer-division` | 정수끼리 나누면 소수점이 사라진다 | 정수 나눗셈 | `hp / maxHp` 는 int 끼리의 나눗셈이라 0.692 가 아니라 0 이다. float 변수에 담아도 늦고, 캐스트는 나누기 전에 걸어야 한다 |
| `tryparse-guard` | TryParse 는 반환값을 확인한다 | TryParse 와 가드 절 | `int.TryParse` 는 성공 여부를 bool 로 돌려주고, 실패하면 out 자리에 0 을 넣는다. 반환값을 확인하는 가드 절이 없으면 0 이 조용히 계산에 흘러간다 |
| `if-chain-order` | if-else if 는 처음 참인 갈래 하나만 | if-else if 사슬 | if-else if 사슬은 위에서부터 조건을 검사하다 처음 참이 된 갈래 하나만 실행한다. 넓은 조건을 먼저 두면 아래 갈래에 닿지 못한다 |

| `break-one-level` | break 는 한 겹만 끝낸다 | break 와 return | 두 겹 for 에서 `break` 는 안쪽 반복문 하나만 끝낸다. 찾자마자 두 겹을 한 번에 나오려면 메서드로 빼고 `return` 한다 |

## 진행 순서

1. `references/<id>/guide.md` 를 읽는다.
2. 같은 폴더의 `.cs` 를 예시로 삼아, 사용자의 코드나 질문에 맞게 줄 단위로 설명한다.
3. 메모리 이야기는 스택의 상자와 힙 객체를 가리키는 화살표로 그린다.
4. guide 의 흔한 실수 목록으로 사용자의 코드를 점검한다.

## 지킬 것

- C# 9 까지만 쓴다. 파일 범위 `namespace X;`, `record struct`, 전역 using 같은 C# 10 이상 문법은 쓰지 않는다 (Unity 6.3).
- 초보자 눈높이로 설명한다. 용어는 값 타입, 참조 타입, 스택, 힙, 메서드, 매개변수, 인자로 통일한다.
- 메모리 이야기는 "스택의 상자"와 "힙의 객체를 가리키는 화살표" 그림으로 설명한다.
- `// [1]` 같은 줄 끝 표시는 웹 갤러리의 단계 보기 표시, `// @param` 은 입력값 표시다. 코드 동작과 상관없다.
- `#if GALLERY_MISTAKE` 구역은 흔한 실수를 재현한 나쁜 예다. 평소에는 꺼져 있다.

## 파일을 다룰 때

- 예시 코드는 실제로 실행해 기록을 남긴 것이다. 출력값을 바꿔 말하지 않는다.
- 표에 없는 개념은 가장 비슷한 표본의 설명 방식(단계, 흔한 실수, Unity 에서는)을 틀로 삼는다.
