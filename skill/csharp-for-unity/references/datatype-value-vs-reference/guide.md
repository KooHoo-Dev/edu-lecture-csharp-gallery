# 값 형식과 참조 형식: 값 복사 · 주소 복사 (Value Types and Reference Types)

교안 4.2 코드를 한 줄씩 실행하며 int 는 값이 통째로 복사되고, 배열은 주소만 복사되어 두 변수가 힙의 배열 하나를 함께 가리키는 것을 본다

개념: 02. 자료형 · 3.3 · 3.4 · 4.2. 난이도 1/3. 주제: 값 형식, 참조 형식, 스택, 힙, 배열.

## 배울 것
- `int b = a;` 직후 a 와 b 가 따로 떨어진 두 상자이고, b 를 바꿔도 a 는 그대로라는 것(값 형식)을 메모리에서 설명할 수 있다.
- `int[] arrB = arrA;` 직후 arrA 와 arrB 가 힙의 배열 하나를 함께 가리키고, 그래서 arrB 로 바꾼 값이 arrA 에도 보인다는 것(참조 형식)을 설명할 수 있다.
- 값 형식은 값을 스택에, 참조 형식은 본체를 힙에 두고 주소를 변수에 둔다는 것을 화면에서 가리킬 수 있다.

## 단계
1. **값이 통째로 복사** (`// [1]` 줄): `int b = a;` 를 실행한 직후다. a 의 값 10 이 **복사되어** 새 상자 b 에 들어갔다. a 와 b 는 값이 같을 뿐 **따로 떨어진 두 상자**다 (3.3 값 형식).
2. **b만 바뀜** (`// [2]` 줄): `b = 20;` 을 실행한 직후다. b 상자만 20 이 되었고 a 상자는 10 그대로다. 복사본을 바꿔도 원본은 영향이 없다. 다음 줄이 `a: 10, b: 20` 을 찍는다.
3. **본체는 힙에** (`// [3]` 줄): `int[] arrA = { 1, 2, 3 };` 을 실행한 직후다. 값 1, 2, 3 을 담은 **배열 본체는 힙**(오른쪽)에 생기고, arrA 상자에는 값이 아니라 **그 본체를 가리키는 주소**(화살표)가 들어갔다 (3.4 참조 형식).
4. **주소만 복사** (`// [4]` 줄): `int[] arrB = arrA;` 를 실행한 직후다. 힙에 배열이 하나 더 생기지 **않았다**. arrA 의 주소가 arrB 에 복사되어 **두 화살표가 같은 배열 하나**를 가리킨다.
5. **arrA에도 반영** (`// [5]` 줄): `arrB[0] = 99;` 를 실행한 직후다. arrB 로 따라가 배열의 첫 칸을 99 로 바꿨는데, arrA 도 같은 배열을 가리키므로 arrA[0] 도 99 다. 다음 줄이 `arrA[0]: 99, arrB[0]: 99` 를 찍는다.

## 흔한 실수 (효과 끄기)
교안 3.4 의 "대입하면 주소만 복사" 를 모르고, `int[] arrC = arrA;` 로 arrA 의 복사본을 만들었다고 생각한 상황이다. 효과 끄기 화면에서는 힙의 배열이 여전히 **하나**이고 arrA · arrB · arrC 세 화살표가 모두 그 배열을 가리킨다. 그래서 `arrC[0] = 50;` 이 arrA 까지 바꿔 마지막 줄이 `arrA[0]: 50, arrC[0]: 50` 을 찍는다. 효과를 켜면 `{ 1, 2, 3 }` 으로 따로 만든 배열이 힙에 하나 더 생겨 `arrA[0]: 99, arrC[0]: 50` 이다.

## 흔한 실수 목록
- **배열을 다른 변수에 대입하고 고쳤더니 원래 배열도 바뀌었다**: 배열은 참조 형식이라 `arrB = arrA` 는 본체가 아니라 주소만 복사한다. 두 변수가 같은 배열을 가리키므로 한쪽으로 바꾸면 다른 쪽에서도 보인다. 따로 쓸 배열이 필요하면 따로 만든다.
- **`int b = a;` 뒤에 b 를 바꿨는데 a 가 그대로라 헷갈린다**: int 는 값 형식이라 대입하면 값이 통째로 복사된다. a 와 b 는 처음부터 다른 상자이고, 이것이 정상 동작이다.
- **`string` 은 참조 형식이라는데 대입한 뒤 한쪽을 바꿔도 다른 쪽이 그대로다**: 교안 3.4 의 예외다. string 은 불변이라 내용을 그 자리에서 고치지 못하고, 다른 문자열을 넣으면 새 문자열이 만들어진다. 그래서 `string s2 = s1;` 뒤에 s2 에 다른 문자열을 넣어도 s1 은 그대로다. 이 갤러리도 문자열은 힙 화살표 없이 상자 안에 값처럼 그린다.
