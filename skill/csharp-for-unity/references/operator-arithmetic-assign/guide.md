# 산술 연산자와 할당 연산자 (Arithmetic and Assignment Operators)

교안 3.1 · 3.2 코드를 한 줄씩 실행하며 산술 연산은 결과만 만들고, 할당은 오른쪽을 먼저 계산해 왼쪽 상자에 덮어쓰는 것을 본다

개념: 03. 연산자 · 3.1 · 3.2. 난이도 1/3. 주제: 산술 연산자, 할당 연산자, 복합 할당, 정수 나눗셈, 나머지.

## 배울 것
- `number + 50` 같은 산술 연산은 결과만 만들어 넘기고 `number` 상자는 바꾸지 않는다는 것을 볼 수 있다.
- 정수끼리의 `/` 는 몫, `%` 는 나머지를 내고, `10 / 3` 이 `3` 이 되는 이유를 설명할 수 있다.
- `number = number + 50;` 이 오른쪽을 먼저 계산한 뒤 그 결과를 왼쪽 상자에 덮어쓴다는 것을 설명할 수 있다.
- `+=` `-=` `*=` `/=` `%=` 가 `변수 = 변수 연산 값` 의 짧은 표기라는 것을 안다.

## 단계
1. **3.1 덧셈** (`// [1]` 줄): `Console.WriteLine(number + 50);` 을 실행한 직후다. 콘솔에 150 이 찍혔지만 메모리의 number 상자는 **그대로 100** 이다. 산술 연산은 결과만 만들어 화면에 넘겼을 뿐이다.
2. **3.1 몫과 나머지** (`// [2]` 줄): `number % 3` 까지 실행한 직후다. 콘솔에 150, 75, 200, 20, 1 이 찍혔다. 정수끼리의 `/` 는 **몫** (100 / 5 = 20), `%` 는 **나머지** (100 = 3 × 33 + 1) 다. 다섯 줄을 지나는 동안 number 는 한 번도 바뀌지 않았다.
3. **3.2 할당** (`// [3]` 줄): `number = number + 50;` 을 처음 실행한 직후다. 오른쪽 `100 + 50` 을 **먼저 계산**하고, 그 결과 150 을 왼쪽 number 상자에 덮어썼다. 이번에는 상자가 바뀐다.
4. **3.2 세 번째** (`// [4]` 줄): 같은 줄을 세 번째로 실행한 직후다. 오른쪽이 매번 지금 값을 읽으므로 100 → 150 → 200 → **250** 으로 불어났다. 수학의 등호라면 성립할 수 없는 식이지만, `=` 는 "넣어라" 라서 몇 번이든 돈다.
5. **3.2 복합 할당** (`// [5]` 줄): `health -= damage;` 를 실행한 직후다. `health = health - damage` 와 같아서 health 는 100 - 30 = **70** 이 됐고, 오른쪽에서 읽기만 한 damage 는 30 그대로다. 앞 줄의 `score += 10` 으로 score 는 50 → 60 이 됐다. 나머지 세 줄까지 마치면 덧붙인 마지막 출력이 `60 70 200 5 0` 을 찍는다 (index 는 4 % 4 = 0 으로 돌아간다).

## 흔한 실수 (효과 끄기)
교안 3.1 표의 "정수 나눗셈이 첫 번째 함정" 이다. 효과 끄기는 `Console.WriteLine(10.0 / 3);` 대신 `Console.WriteLine(10 / 3);` 을 실행한다. 양쪽이 int 라 결과도 int 가 되어 콘솔 여섯째 줄이 `3.3333333333333335` 가 아니라 **3** 으로 찍힌다. 오류 없이 소수점 아래가 사라지므로 비율을 계산할 때 할인이 통째로 0 이 되는 버그 (교안 4절) 로 이어진다.

## 흔한 실수 목록
- **`10 / 3` 이 3.33 이 아니라 3 으로 나온다**: 양쪽이 int 면 결과도 int 라 소수점 아래가 버려진다. 한쪽을 실수로 만든다: `10.0 / 3` 이나, 변수라면 `(double)a / b`.
- **`20 / 100` 으로 할인율을 구했더니 할인이 되지 않는다**: 정수 나눗셈이라 `20 / 100` 은 0 이다. 비율을 계산할 때는 `20 / 100.0` 처럼 나누는 쪽 어딘가에 실수를 섞는다.
- **`number + 50;` 을 했는데 number 가 그대로다**: 산술 연산은 결과를 만들 뿐 변수를 바꾸지 않는다. 바꾸려면 `number = number + 50;` 이나 `number += 50;` 처럼 할당해야 한다.
- **`=` 를 "같다" 로 읽어 `number = number + 50` 이 이해되지 않는다**: `=` 는 오른쪽을 계산해서 왼쪽에 넣으라는 명령이다. "같다" 를 묻는 것은 `==` 다.

## Unity 에서는
1. 이 표본은 교안과 같은 콘솔 프로그램(최상위 문)이다. `dotnet new console` 로 프로젝트를 만들고 Program.cs 에 원본을 붙여 넣는다.
2. `dotnet run` 으로 실행해 콘솔 출력을 무대의 콘솔 칸과 비교한다. 입력값이 있으면 무대에서 고른 입력을 그대로 친다.

확인: 콘솔 출력이 무대의 콘솔 칸과 같다.

- Unity 에서는 `Console.WriteLine` 대신 `Debug.Log` 로 찍는다. `Console.ReadLine` 은 Unity 에서 입력을 받지 못한다.
- 최상위 문(클래스와 Main 없이 쓰는 코드)은 Unity 스크립트에 그대로 넣을 수 없다. MonoBehaviour 의 `Start()` 안으로 옮긴다.
