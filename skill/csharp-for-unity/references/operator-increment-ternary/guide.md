# 증감 · 삼항 연산자와 우선순위 (Increment, Ternary and Precedence)

교안 3.5 ~ 3.7 을 한 줄씩 실행하며 전위 ++ 와 후위 ++ 가 넘기는 값의 차이, 삼항이 고르는 값, 괄호가 바꾸는 결과를 본다

개념: 03. 연산자 · 3.5 · 3.6 · 3.7. 난이도 1/3. 주제: 증감 연산자, 전위 후위, 삼항 연산자, 우선순위, 괄호.

## 배울 것
- `++count;` 와 `count++;` 를 한 줄에 홀로 쓰면 둘 다 1 씩 올린다는 것을 볼 수 있다.
- 값을 다른 곳에 넘길 때 전위는 올린 값을, 후위는 올리기 전 값을 넘긴다는 것을 메모리 상자로 설명할 수 있다.
- `score >= 90 ? "A" : "B"` 가 조건 하나로 두 값 중 하나를 고른다는 것을 안다.
- `&&` 가 `||` 보다 먼저 묶이므로, 의도한 묶음은 괄호로 드러내야 한다는 것을 안다.

## 단계
1. **3.5 전위 홀로** (`// [1]` 줄): `++count;` 를 실행한 직후다. count 상자가 0 에서 1 이 됐다. 다음 줄 `count++;` 도 홀로 쓰여서 똑같이 1 을 올린다 (콘솔 첫 줄 2). **한 줄에 홀로 쓰면 둘은 완전히 같다.**
2. **3.5 전위로 넘기기** (`// [2]` 줄): `int prefix = ++count;` 를 실행한 직후다. 전위는 **먼저 1 올리고** 그 값을 쓴다. count 가 2 → 3 이 된 다음 그 3 이 prefix 상자에 들어갔다.
3. **3.5 후위로 넘기기** (`// [3]` 줄): `int postfix = count++;` 를 실행한 직후다. 후위는 **지금 값을 먼저 쓰고** 그 다음 1 올린다. postfix 상자에는 올리기 전 값 3 이 들어갔고, count 는 그 뒤에 4 가 됐다. 같은 "1 올리기" 인데 넘긴 값이 다르다.
4. **3.6 삼항** (`// [4]` 줄): `string grade = score >= 90 ? "A" : "B";` 를 실행한 직후다. score 가 85 라 `score >= 90` 이 거짓이어서 뒤쪽 값 "B" 가 골라져 grade 상자에 들어갔다. 입력값에서 score 를 90 으로 바꾸면 "A" 가 된다.
5. **3.7 괄호** (`// [5]` 줄): `bool result = a && (b || c);` 를 실행한 직후다. 괄호 안 `b || c` 가 먼저 계산돼 true, 그다음 `a && true` 는 a 가 false 라 result 는 **false** 다. "a 이면서" 라는 의도대로다. 괄호를 빼면 어떻게 되는지는 효과 끄기에서 본다.

## 흔한 실수 (효과 끄기)
교안 3.7 과 8절의 "`&&` 와 `||` 를 괄호 없이 섞음" 이다. 효과 끄기는 `a && (b || c)` 대신 `a && b || c` 를 쓴다. `&&` 가 `||` 보다 먼저라 `(a && b) || c` 로 묶여, `false || true` 가 되어 result 상자가 **true** 가 되고 마지막 출력도 `True` 로 바뀐다. 의도는 "a 이면서" 인데 a 가 false 여도 c 하나로 통과해 버린다. 오류 없이 결과만 뒤집힌다.

## 흔한 실수 목록
- **`count++` 를 넘겼는데 올린 값이 아니라 이전 값이 들어갔다**: 후위는 지금 값을 먼저 쓰고 그 다음 올린다. 올린 값을 넘기려면 전위 `++count` 를 쓰거나, 올리는 줄과 쓰는 줄을 나눈다.
- **`A && B || C` 가 생각과 다른 결과를 낸다**: `&&` 가 `||` 보다 먼저 묶여 `(A && B) || C` 로 해석된다. 우선순위를 외우지 말고 묶이는 단위를 괄호로 드러낸다.
- **삼항을 여러 번 겹쳤더니 어디서 갈라지는지 읽히지 않는다**: 중첩 삼항은 눈으로 따라가기 어렵다. 삼항은 1단계까지만 쓰고, 갈래가 셋을 넘으면 `if-else if` 로 푼다.
- **`score > 90` 으로 썼더니 90점이 A 가 되지 않는다**: 경계값을 넣으려면 `>=` 를 쓴다. 판정식을 쓸 때는 경계를 넣을지 뺄지를 먼저 정한다.
